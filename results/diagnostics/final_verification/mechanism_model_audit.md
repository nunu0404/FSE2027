# F5 Mechanism Model Audit

## Verdict

The manuscript phrase "gradient boosting over 632 features" is incorrect. Both mechanism tables have **632 total columns**, but the predictive model selects **268 engineered pair features**: 164 source-derived and 104 pixel-derived visual/layout features. It additionally uses three numeric controls (`abs_human_score_gap`, `rf_margin_abs`, `rf_margin_percentile`) and categorical `difficulty`. There are no OCR or VLM-derived predictors.

The published AUCs are reproducible as pair-level 5-fold out-of-fold (OOF) AUCs, not held-out-test AUCs. The folds are not snippet-disjoint, so repeated snippets can occur in training and validation. The values should be described as explanatory cross-validation, not deployment performance.

## Inputs and feature units

- Java data: `/ANON/experiment_root/results/complementarity_mechanism_clean_qwen_text_plus_image_20260706/final_mechanism_dataset.csv`, 3,000 pairs x 632 total columns.
- Python/CUDA data: `/ANON/experiment_root/results/python_cuda_missing_experiments_20260716/mechanism_qwen_text_plus_image/final_mechanism_dataset.csv`, 6,000 pooled pairs x 632 total columns.
- Builder/model code: `/ANON/experiment_root/results/python_cuda_missing_experiments_20260716/code/run_complementarity_mechanism_analysis.py`, fields selected at lines defining `feature_cols` and `model_frame`.
- Source features are first calculated per snippet from source code, then converted to pair summaries/differences.
- Visual features are first calculated per rendered PNG directly from pixels without OCR, then converted to pair summaries/differences.
- Pair operations retained by the model are suffixes `_diff_abs`, `_gold_minus_loser`, `_mean`, and `_max`.
- Targets and RF-margin controls are pair-level. No call-level feature is used.

The preprocessor median-imputes and standardizes numeric fields, and one-hot encodes difficulty. Depending on present difficulty categories, the transformed design has more columns than the 272 raw predictors, but neither value is 632 features.

## Targets

1. `RF failure`: all pairs; target is `not rf_correct`.
2. `VLM rescue`: RF-wrong pairs; positive means VLM is strict-swap-valid and correct, while wrong and invalid are negative.
3. `valid-pair correctness`: RF-wrong and VLM-valid pairs only; positive means VLM correct and negative means VLM wrong.

The VLM analyzed for the headline values is Qwen2.5-VL-7B `text_plus_image`.

## Historical model and split

- Models compared: balanced logistic regression; depth-3 balanced decision tree with minimum leaf 25; 300-tree balanced random forest with maximum depth 5 and minimum leaf 10; default gradient boosting with `random_state=42`.
- Reported best model: gradient boosting.
- Evaluation: `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)` plus `cross_val_predict` probabilities.
- Tuning: none. Hyperparameters are fixed in the script; no nested CV.
- Split unit: pair row. Exact pair/reverse-order duplication is not present as separate rows, but endpoints recur across many rows, so snippets leak across folds.
- Java is analyzed separately; Python and CUDA are pooled, with no language indicator in the headline model.

## Eight-condition visual increment

The eight conditions are Qwen and InternVL crossed with `image_only`, `text_plus_image`, `combined_labeled_image_only`, and `combined_labeled_text_plus_image`. The claimed rescue increment is `AUC(source+visual) - AUC(source-only)` on pair-level OOF predictions.

The original bootstrap used 2,000 ordinary row-resampling replicates, with condition-specific seeds beginning at 20260716. It did not cluster by pair endpoint and did not adjust across the eight effective-rescue tests. Five unadjusted p-values are below .01, with increments 0.00886 to 0.02767 AUC (0.89 to 2.77 points). After Holm correction over the eight effective-rescue tests, only InternVL combined-image-only (`p=.001`, Holm `.008`) remains below .05. Therefore the manuscript must call these **unadjusted bootstrap p-values** or replace the multiplicity claim.

Sources:

- `/ANON/experiment_root/results/python_cuda_missing_experiments_20260716/code/run_python_cuda_all_condition_ablation.py`

Feature-association Mann-Whitney tests use all rows with BH-FDR adjustment and are descriptive in-sample associations, not held-out findings.

## Snippet-disjoint sensitivity

New analysis, kept separate from historical results:

- Script: `/ANON/experiment_root/results/fse2027_final_verification/code/recompute_mechanism_snippet_disjoint.py`
- Output: `/ANON/experiment_root/results/fse2027_final_verification/mechanism_snippet_disjoint_auc.csv`
- Seed: 42; five deterministic language-stratified snippet folds.
- For fold k, test pairs have both endpoints in k and training pairs have neither endpoint in k. Crossing edges are excluded. This guarantees no snippet overlap, but only evaluates within-fold edges, so coverage is explicitly reported and the sensitivity is not a replacement for the historical estimate.

| Scope | Target | evaluated / available | Snippet-disjoint AUC | Balanced accuracy |
|---|---|---:|---:|---:|
| Java | RF failure | 571 / 3,000 | 0.8560 | 0.7501 |
| Java | VLM rescue | 200 / 1,130 | 0.6559 | 0.6041 |
| Java | Valid-pair correctness | 155 / 856 | 0.6913 | 0.6340 |
| Python/CUDA pooled | RF failure | 1,155 / 6,000 | 0.9180 | 0.8078 |
| Python/CUDA pooled | VLM rescue | 387 / 1,914 | 0.7282 | 0.6819 |
| Python/CUDA pooled | Valid-pair correctness | 283 / 1,399 | 0.8109 | 0.7335 |

All headline AUCs decline, especially rescue/correctness. The qualitative result that outcomes are predictable remains, but the original magnitudes are optimistic under snippet overlap.

In the same snippet-disjoint sensitivity, visual increments across the eight rescue conditions range from -0.0193 to +0.0468 AUC; six are positive and two are negative. No inferential p-values are claimed for this low-coverage sensitivity.

Reported AUCs are five-fold stratified pair-level OOF estimates (Java: n=3,000; Python/CUDA pooled: n=6,000; seed 42); because snippets recur across pair folds, we treat them as explanatory and report a separate endpoint-disjoint sensitivity analysis."
